# 词性分类 + 活用表 设计文档

> 2026-06-23 · 在「词库」词汇浏览基础上,增加词性筛选与动词/形容词活用表。
> 本期目标:**能查**(参考工具)。练习/SRS 留作下一期。

## 1. 问题陈述

词汇表目前只把 `pos` 当一列乱码文本展示,无法按词性筛选;更关键的是日语动词/形容词的各种活用形(た/て/ます/ない/可能/受身/使役…)是学习难点,系统完全没有。用户需要:点开一个词就能看到它的词性分类和完整活用表,作为随时查阅的工具。

## 2. 关键事实(已验证)

- **`pos` 字段已编码动词类别**(中文教材体系):`動1`=五段、`動2`=一段、`動3`=サ变/カ变;前缀 `自/他/自他` 表及物性;还有 `名/イ形/ナ形/副` 等。一词常多类(如 `名・自他動3`)。
- **pos 同时混入音调标记**(circled `⓪①②③`,如 `自動3①`)与「文章語」等备注 → 归一化时须剔除。
- **`sudachipy` 已是依赖且可用**,对词条返回精确活用型:`五段-マ行`/`下一段-バ行`/`サ行変格`/`カ行変格`,并能区分 する(サ変)与 来る(カ変)。
- 动词类型用 **sudachi 为主**(拿到具体「行」+ 区分サ変/カ変),pos 的动1/2/3 作为**用户可读的友好标签**(一类/二类/三类)。

## 3. 需求

### 功能需求
1. **词性归一化**:把乱码 `pos` 映射成结构化标签 `{categories:[名词/动词/イ形容词/ナ形容词/副词/其他], transitivity:自/他/自他, verb_group:五段/一段/サ变/カ变}`。一词可属多类。
2. **词性筛选(细分)**:列表上按 名词/动词(再拆 自动词/他动词)/イ形/ナ形/副词/其他 筛选。一词多类时多个筛选都命中。
3. **活用表(详情面板)**:点词条 → 右侧抽屉/弹窗显示该词 词性 + 完整活用表。
   - 动词:**12+ 形** — 辞书形、ます形、て形、た形、ない形、なかった形、可能形、意志形、受身形、使役形、使役受身形、命令形、禁止形、条件形(ば/たら)。
   - イ形容词:现在/过去/否定/过去否定/て形/副词形(く)。
   - ナ形容词:だ/だった/じゃない/じゃなかった/で/な(连体)。
   - 名词、副词等不变形 → 面板只显示词性,不显示活用表(或注明"此词不变形")。

### 非功能需求
- 活用生成**确定性、可测**:规则引擎 + 全量单测(TDD),每个动词组 + 不规则各有用例。
- 活用**按需计算**(点开词条时),不改 DB schema、不预存;可加内存缓存。
- 不破坏现有词库浏览与测试。

## 4. 设计

### 4.1 后端
- **`app/services/jpos.py`**(词性归一化):`normalize_pos(raw: str) -> dict`。剔除 circled 音调与备注,按分隔符 `・/，　` 拆分,映射到结构化标签。
- **`app/services/conjugation.py`**(活用引擎):`conjugate(headword, reading, pos) -> dict | None`。
  - 用 sudachi 取活用型与「行」;不规则按 lemma 特判。
  - 在 **reading(かな)** 上做活用保证正确,再回贴 kanji 表层(headword 有汉字时)。
  - 返回 `{"type":"verb|i-adj|na-adj", "group":"五段", "forms":[{"key":"て形","label":"て形","kana":"のんで","surface":"飲んで"}, ...]}`;不变形返回 `None`。
- **API**:
  - 列表接口 `GET /api/vocab` 增加 `pos` 筛选参数(值如 `verb`/`verb_t`/`verb_i`/`noun`/`i-adj`/`na-adj`/`adv`/`other`),并在每个 item 附 `pos_tags`(归一化结果,供前端展示小标签)。`counts` 仍随 q 联动。
  - 详情 `GET /api/vocab/{id}` → `{...词条, pos_tags, conjugation}`(conjugation 可为 null)。

### 4.2 前端
- 列表:词性筛选器(名词/动词▾(自/他)/イ形/ナ形/副词/其他);每行词性列显示归一化小标签。
- **详情抽屉组件 `VocabDetail.tsx`**:点行打开,展示 写法/读音/释义/词性 + 活用表(按"基本形/丁寧/否定/使役受身/条件…"分组,かな+汉字表层对照)。
- `lib/api.ts` 加 `getVocabDetail(id)`;`types.ts` 加 `PosTags`/`Conjugation` 类型。

## 5. 对抗性分析(活用引擎的坑 → 都要有测试)

| 风险 | 处理 |
|---|---|
| 五段音便 | く→いて/いた、ぐ→いで、う/つ/る→って、ぬ/ぶ/む→んで、す→して |
| **行く** 例外 | 五段カ行但 て/た形 = 行って/行った(按 lemma 特判) |
| **来る** 读音变 | くる→こない/きます/こい/こよう(かな词干变,需特判,汉字表层 来ない=きない) |
| **する** | して/した/しない/できる(可能)/される/させる/しろ・せよ/しよう |
| **ある** | 否定 = ない(非 あらない);其余正常 |
| 敬语五段 おっしゃる/くださる/なさる/いらっしゃる | ます形 = おっしゃいます(い 非 り)、命令特殊 |
| **いい/良い** | よくない/よかった/よくて(非 いくない) |
| サ变名词(名・サ変,如 勉強) | 以「+する」活用展示 |
| 一词多 pos / 同形多读 | 有动词读法才出动词表;归一化合并多类 |
| kana-only 词条 | 直接用 reading,无 kanji 表层 |
| pos 含音调 circled 数字/「文章語」 | 归一化先剔除再解析 |

## 6. 成功标准
- 词库列表能按细分词性筛选,词性小标签正确。
- 点常见动词(飲む/食べる/する/来る/行く/ある)、イ形(高い/いい)、ナ形(静か)→ 活用表全部正确。
- 活用引擎单测覆盖五段各行 + 一段 + サ变/カ变 + 全部上述不规则,全绿。
- 不变形词(名词/副词)详情面板优雅处理。
